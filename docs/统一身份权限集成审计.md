# Casdoor × OpenBuddy × Resource Gateway × WeKnora 集成审计

审计日期：2026-08-30。本文只记录代码、测试和目标 Casdoor 实例的可验证事实；“代码测试通过”不等于远端配置完成或生产上线。

## 结论

- 统一身份链路的代码骨架已完成：Casdoor OIDC → OpenBuddy 主进程 → Gateway token exchange → WeKnora 本地会话与知识库 ACL。
- 统一主体键是 `issuer + sub`；组织到 WeKnora tenant 必须使用显式映射，不能因首次登录自动创建生产租户。
- WeKnora exchange token 有效期 5 分钟，Gateway introspection 会在每次 WeKnora 验证时重新检查成员撤销和租户授权版本；Casdoor 用户、角色、权限、组或组织变更触发的 webhook 会递增该租户的 authorization_version，从而让旧 token 立即失效。
- 现在 token exchange 同时要求统一 WeKnora 权限词典中的一个权限：`weknora.platform.admin`、`weknora.workspace.read`、`weknora.workspace.contribute`、`weknora.workspace.admin` 或 `weknora.workspace.owner`。只有租户成员资格或 `isAdmin` 不能换取 WeKnora token。
- 目标 Casdoor 实例 Discovery 可达，`admin/openbuddy` 应用的 `redirectUris/scopes/enableCodeSignin` 仍为空，因此 PKCE 流程尚不能完成；仅 `password` grant 探测到管理员账号可签发 `openid` scope 的 access token，但该 token 的 `azp=005d6839fe25abd6696f`，不能作为 PKCE 登录成功或 production 接入完成的证据。

## 实际数据流

1. OpenBuddy 系统浏览器打开 Casdoor Authorization Code + PKCE；token 只进入 Electron 主进程，不进入 renderer、URL 或日志。
2. 主进程按 Casdoor organization 解析 active tenant，并用显式 `OPENBUDDY_WEKNORA_TENANT_MAP` 映射到 WeKnora tenant ID。
3. 知识库列表先做 `weknora.workspace/read` 远程授权，再调用 Gateway exchange；问答使用 `weknora.workspace/contribute`。
4. Gateway 校验 Casdoor JWT、issuer/audience、签名、过期、租户 membership、撤销状态、tenant mapping、统一 WeKnora 权限和租户 authorization_version，然后签发 HS256 exchange token。
5. WeKnora 校验 exchange token 的 issuer、audience、类型、主体、租户、session、membership version、authorization_version、jti，并调用 Gateway introspection；随后仍由本地 tenant membership、KB ACL 和路由 RBAC 做最终授权。

## 未完成与上线门禁

1. Casdoor OpenBuddy 应用 `admin/openbuddy`（client ID `005d6839fe25abd6696f`）必须登记精确回调 `casdoor://localhost/callback`、`openid profile email`（按需 `offline_access`）和授权码登录能力；当前两个脱敏 endpoint 都返回空对象，PKCE 流程尚不可用。
2. 生产必须使用 HTTPS、专用 Casdoor application、独立 client secret、强随机 Gateway exchange secret、SQL 持久化 store、webhook/backchannel secret 和明确 tenant map。
3. OpenBuddy 生产必须设置 `OPENBUDDY_CASDOOR_REQUIRE_REMOTE_ENFORCEMENT=true`，并在 Casdoor 中把统一点号权限映射到 resource/action：`weknora.workspace.read` 对应 object `weknora.workspace`、action `read`，其余动作同理。仅 `password` grant 探测到管理员账号可签发 `openid` scope 的 access token，但这不是 PKCE 登录成功。
4. introspection endpoint 只允许 WeKnora 私网或受认证反向代理访问，不应直接公开到互联网。Gateway 持久化层（`schemaVersion=13`）已包含 `authorizationVersions`，升级到 Postgres/MySQL 时需要一次性回填。
5. 仍缺真实普通成员 E2E：登录、租户选择、允许/拒绝、exchange、KB 列表、SSE 问答、引用、撤销后旧 token、跨租户拒绝、logout/backchannel/webhook、role/permission 变更后旧 token 立即失效。

### E. 错位部署的典型失败信号

| 现场症状 | 大概率原因 |
|---|---|
| Gateway 返回 401 `AUTHENTICATION_REQUIRED` | OpenBuddy 未把 Casdoor bearer 透传到 exchange；或 issuer/client 不一致 |
| Gateway 返回 403 `TOKEN_EXCHANGE_TENANT_MAPPING_REQUIRED` | 三处 tenant map 不一致（OpenBuddy / Gateway / WeKnora） |
| Gateway 返回 403 `WEKNORA_PERMISSION_REQUIRED` | Casdoor 中没有把五项统一权限建模到当前主体；OpenBuddy 远程 `/api/enforce` 也未拿到该资源权限 |
| Gateway 返回 403 `AUTHORIZATION_VERSION_REVOKED` | 上一次 Casdoor webhook 已 bump 版本；用户需要重新登录换 token |
| WeKnora 返回 “gateway exchange token missing tenant” / “tenant mapping is not configured” | WeKnora 端 `OIDC_AUTH_GATEWAY_TENANT_MAP` 与 Gateway/OpenBuddy 不一致，或 `casdoor_tenant` claim 为空 |
| WeKnora 返回 “gateway exchange token is no longer active” | introspection 失败（introspection URL 不可达、secret 不匹配、token 被 revoke 或 authorization_version 已 bump） |

| 步骤 | 请求 | 实际响应 |
|---|---|---|
| 健康检查 | `GET /healthz` | `{"status":"ok","data":{"ok":true,"store":"memory","version":"dev","latencyMs":0}}` |

## 2026-08-31 23:30 真实 PKCE-exchange 端到端验收

按用户授权，使用 `admin/123` 在远端 Casdoor 上对 `admin/openbuddy` 应用与五个统一权限做了最小补丁与最小真实 E2E：

1. 远端 Casdoor `admin/openbuddy` 应用补丁（API `POST /api/update-application`，仅添加、不删）：
   - `redirectUris = ["casdoor://localhost/callback"]`；
   - `scopes = [{name:"openid"},{name:"profile"},{name:"email"},{name:"offline_access"}]`；
   - `enableCodeSignin = true`；
   - `grantTypes` 含 `authorization_code`（其余由 Casdoor 自动补齐）。
2. 在 `built-in` organization 下建模五个统一权限（API `POST /api/add-permission`），每条 `resourceType=Application`、`resources=[admin/openbuddy]`、`effect=Allow`、`isEnabled=true`，并把它们加到 `built-in/openbuddy-admin` 角色的 `permissions` 字段。
3. 用 `admin/123` + `005d6839fe25abd6696f` 走 `password` grant 拿到的 access token 现在 `permissions` claim 包含五个 `weknora.*` 对象。
