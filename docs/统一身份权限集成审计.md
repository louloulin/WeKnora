# Casdoor × OpenBuddy × Resource Gateway × WeKnora 集成审计

审计日期：2026-08-30。本文只记录代码、测试和目标 Casdoor 实例的可验证事实；“代码测试通过”不等于远端配置完成或生产上线。

## 结论

- 统一身份链路的代码骨架已完成：Casdoor OIDC → OpenBuddy 主进程 → Gateway token exchange → WeKnora 本地会话与知识库 ACL。
- 统一主体键是 `issuer + sub`；组织到 WeKnora tenant 必须使用显式映射，不能因首次登录自动创建生产租户。
- WeKnora exchange token 有效期 5 分钟，Gateway introspection 会在每次 WeKnora 验证时重新检查成员撤销，撤销不需要等待 token 自然过期。
- 现在 token exchange 同时要求统一 WeKnora 权限词典中的一个权限：`weknora.platform.admin`、`weknora.workspace.read`、`weknora.workspace.contribute`、`weknora.workspace.admin` 或 `weknora.workspace.owner`。只有租户成员资格或 `isAdmin` 不能换取 WeKnora token。
- 目标 Casdoor 实例 Discovery 可达，但 OpenBuddy 应用仍缺少真实 OIDC 前置配置，尚未完成普通成员授权码 PKCE 到问答 SSE 的生产实测。

## 实际数据流

1. OpenBuddy 系统浏览器打开 Casdoor Authorization Code + PKCE；token 只进入 Electron 主进程，不进入 renderer、URL 或日志。
2. 主进程按 Casdoor organization 解析 active tenant，并用显式 `OPENBUDDY_WEKNORA_TENANT_MAP` 映射到 WeKnora tenant ID。
3. 知识库列表先做 `weknora.workspace/read` 远程授权，再调用 Gateway exchange；问答使用 `weknora.workspace/contribute`。
4. Gateway 校验 Casdoor JWT、issuer/audience、签名、过期、租户 membership、撤销状态、tenant mapping 和统一 WeKnora 权限，然后签发 HS256 exchange token。
5. WeKnora 校验 exchange token 的 issuer、audience、类型、主体、租户、session、membership version、jti，并调用 Gateway introspection；随后仍由本地 tenant membership、KB ACL 和路由 RBAC 做最终授权。

## 未完成与上线门禁

1. Casdoor OpenBuddy 应用必须登记精确回调 `casdoor://localhost/callback`、`openid profile email`（按需 `offline_access`）、Authorization Code + PKCE；当前脱敏审计仍显示 `redirectUris=[]`、`scopes=[]`、`enableCodeSignin=false`。
2. 生产必须使用 HTTPS、专用 Casdoor application、独立 client secret、强随机 Gateway exchange secret、SQL 持久化 store、webhook/backchannel secret 和明确 tenant map。
3. OpenBuddy 生产必须设置 `OPENBUDDY_CASDOOR_REQUIRE_REMOTE_ENFORCEMENT=true`，并在 Casdoor 中把统一点号权限映射到 resource/action：`weknora.workspace.read` 对应 object `weknora.workspace`、action `read`，其余动作同理。
4. introspection endpoint 只允许 WeKnora 私网或受认证反向代理访问，不应直接公开到互联网。
5. 仍缺真实普通成员 E2E：登录、租户选择、允许/拒绝、exchange、KB 列表、SSE 问答、引用、撤销后旧 token、跨租户拒绝、logout/backchannel/webhook。

## 不应宣称的内容

- 不能把管理员接口只读访问或 Discovery 可达称为登录成功。
- 不能把本地模拟 Casdoor claims 称为真实 Casdoor policy 生效。
- 不能把 `127/127`、`133/133` 称为生产 E2E。
- 当前状态应表述为：**代码集成和本地回归完成；远端 Casdoor 应用配置、生产部署和真实普通成员全链路验收未完成。**
