二、数据模型（迁移 110 / 111）

-- 110: 持久化 Yjs 文档快照（Postgres）
CREATE TABLE wiki_doc_snapshots (
    id BIGSERIAL PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    kb_id VARCHAR(36) NOT NULL,
    page_id VARCHAR(36) NOT NULL,
    ydoc_state BYTEA NOT NULL,
    vector_clock BYTEA NOT NULL DEFAULT decode('', 'hex'),
    version BIGINT NOT NULL DEFAULT 1,
    size_bytes INT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (tenant_id, kb_id, page_id)
);
CREATE INDEX idx_wiki_doc_snapshots_tenant ON wiki_doc_snapshots (tenant_id);
CREATE INDEX idx_wiki_doc_snapshots_updated ON wiki_doc_snapshots (updated_at DESC);
-- trigger auto-bumps updated_at + version

-- 111: 实时 presence / awareness 行
CREATE TABLE wiki_realtime_sessions (
    id VARCHAR(36) PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    page_id VARCHAR(36) NOT NULL,
    user_id BIGINT NOT NULL,
    client_id BIGINT NOT NULL,
    color VARCHAR(16) NOT NULL DEFAULT '#58a6ff',
    display_name VARCHAR(128) NOT NULL DEFAULT '',
    last_heartbeat TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    joined_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (tenant_id, page_id, client_id)
);
CREATE INDEX idx_wiki_realtime_sessions_page ON wiki_realtime_sessions (page_id, last_heartbeat DESC);

四、关键流程

Client-A (Tiptap+Yjs)          Server (Gin+gorilla/ws)         Client-B (Tiptap+Yjs)
       │                                  │                                  │
       │ 1. WS upgrade /api/v1/knowledgebase/:kbId/wiki/realtime/:pageId?token=...
       │─────────────────────────────────▶│                                  │
       │                                  │ 2. JWT 验证 (URL query token)    │
       │                                  │ 3. AuthZ phase-3 write check     │
       │                                  │ 4. y-websocket hub.attach        │
       │◀──── sync_step2 (snapshot) ─────│                                  │
       │                                  │                                  │
       │ 5. user edits → ydoc.transact    │                                  │
       │─────── update (delta) ──────────▶│                                  │
       │                                  │ 6. fan-out to peers              │
       │                                  │────────── update (delta) ───────▶│
       │                                  │                                  │
       │                                  │ 7. heartbeat → awareness table   │
       │                                  │    (idle > 30s → sweep)          │
       │                                  │                                  │
       │                                  │ 8. snapshot every 5min or 256KB  │
       │                                  │    → wiki_doc_snapshots          │

五、协议层（y-websocket wire format）

消息TypeSubtypePayload
messageSync0——
sync_step100state vector (16+ bytes)
sync_step201missing updates (Yjs binary)
sync_update02new delta (Yjs binary)
messageAwareness1—awareness delta (cursor / selection)

Frame: 1B length + 1B type + N bytes payload. v0.7.19 上限 127 字节/帧，足够覆盖大多数 Yjs delta；大快照走专用 snapshot frame（v0.7.20）。

九、风险与缓解

风险等级缓解

多实例协同中v0.7.19.x 引入 Redis pub/sub 复用 AuthZ phase-3 模式
Yjs 大文档膨胀中5min/256KB 压缩 + 历史 purge（保留 N 个版本）
