二、v0.7.16 增量 — GeoIP 接入

2.1 架构

登录流：

c.ClientIP → ConditionalAccessService.Evaluate → FillCountryFromIP → CountryResolver.Lookup → CountryCode → MatchConditions

2.2 三种 Resolver

· Noop：默认，永远 miss（保持 v0.7.14 行为）

· Static：手工维护 CIDR→国家表（测试 + 小型部署）

· MMDB：MaxMind GeoLite2（生产）— -tags geoipmmdb 编译开关

2.3 测试覆盖（9 项）

geoiplookup：

· NoopCountryResolver_AlwaysMisses

· StaticCountryResolver_BasicMatch

· StaticCountryResolver_CountryIsUppercased

· StaticCountryResolver_DropsInvalid

· StaticCountryResolver_Add

· StaticCountryResolver_IPv6

condaccgeoip：

· FillCountryFromIP_NoResolver

· FillCountryFromIP_PreservesSuppliedCountry

· FillCountryFromIP_Resolves

风险提示：v0.7.16 没有改 Evaluate 的语义：caller-supplied CountryCode 仍然优先生效；这保留了 v0.7.14 已知的所有调用方行为，Auto-fill 是 add-on 不替代。MMDB 真集成放到 v0.7.16.x，避免一次引入 CGO 与新依赖。

三、Notion AI Agent 框架（Custom Agents / Workers）

基于 notion.com/product/ai, notion.com/help/custom-agents, 2025-2026 资料。

Notion Agent（基础）

· Chat、Generate、Autofill、Translate、Research Mode

· 内置 30+ Action（写入数据库、生成页面、查询 AI Meeting Notes）

· 输入：当前页 + 显式 prompt；输出：可应用到页面的内容

· 模型：模型无关（可切 Anthropic / OpenAI / 自托管）

· 计费：Notion Credits

Custom Agents（可复用）

· 构建一次，工作区共享

· 自定义 instructions + 工具集 + 数据源连接器

· 用户可在页面里 @Custom-Agent 触发

· 计费：$10 / 1k credits（post-trial）

· 治理：workspace admin 可禁 / 限

Notion Workers（开发者平台，2026 Beta）

· 自托管运行平台：可以跑自定义代码（基于 Notion Runtime）

· Agent 工具：可调用 Workers（HTTP / DB / 第三方 API）

· 触发：Webhook + Schedule + Agent Action

· 计费：credits-based

· 沙箱：每 Worker 独立 runtime + 资源配额

与 WeKnora 对照：WeKnora 已有 agent_service.go 基础 Agent（chat + tool call + memory），但缺 Custom Agent 抽象（instructions 模板 + 工具集 + 工作区共享），更缺 Workers 这种开发者平台。要补 v0.7.21+。

四、飞书 AI / 妙搭 / aily / 豆包工作伙伴

基于 feishu.cn/product/feishuai, 2025-2026 资料。

飞书 AI / 知识问答

· 知识问答：跨知识库 + Wiki + 邮件 RAG 问答

· 智能会议纪要（Miaojì）：实时转写 + 章节 + 待办提取

· 豆包工作伙伴：通用 AI 助手（豆包大模型）

· AI 字段：自动生成（摘要 / 翻译 / 提取 / 分类）

· AI 仪表盘：基于多维表的智能洞察

飞书妙搭（低代码 AI Apps）

· 拖拽搭建 AI 应用：输入源 → AI 节点 → 输出节点

· 可发布到飞书工作台为应用

· 触发：表单 / 按钮 / Webhook / 定时

· 模型：豆包 + 第三方可接入

· 计费：AI credits 包（与飞书 AI 同）

aily desktop + 飞书项目 AI

· aily：AI 入口 + 企业智能体编排

· 桌面端：跨应用 AI 助手（mac / win）

· 飞书项目 AI：需求 → 任务自动拆解 / 风险预警

· 集成：飞书全家桶 + 第三方 API

· 治理：管理员可限可用 AI 能力 + 数据脱敏

与 WeKnora 对照：飞书在 AI 方面把「文档 → 知识 → AI 应用 → Agent」打通了一个完整链路。WeKnora v0.7.15 后端只到「知识问答」这一环，距离「妙搭级别 AI Apps」还有 2-3 个版本。

五、Confluence Rovo / Rovo Studio / Rovo Agents

基于 atlassian.com/platform/rovo, 2025-2026 资料。

Rovo Search

· 跨 Atlassian Cloud + 第三方 connector 检索

· 答案带源链接 + 引文

· 模型无关（Anthropic / OpenAI / Azure OpenAI 路由）

Rovo Chat / Rovo Agents

· Chat：自由问答 + Action 触发

· Agents：可编排的 agent（研究 / 客户支持 / 销售）

· 触发：手动 + 自动（基于事件）

· 上下文：Teamwork Graph（人 / 项目 / 内容 / 目标）

Rovo Studio / Rovo Dev CLI / MCP

· Studio：可视化 agent builder

· Dev CLI：CLI 编排 agent

· MCP server：MCP 协议兼容（Claude Desktop 等可直连）

· Marketplace：可发布到 Atlassian Marketplace

与 WeKnora 对照：Rovo 走的是「Teamwork Graph + Agent 编排 + MCP」路线。WeKnora AuthZ 元组模型（v0.7.4-8）已经有 graph 的雏形，但缺「自动建图 / Rovo Studio / MCP」。MCP 集成最值得先做（v0.7.21 候选）。

六、Glean Agents / Glean Studio / Glean MCP

基于 glean.com, docs.glean.com, 2025-2026 资料。

Glean Assistant

· 模型无关（Anthropic / OpenAI / Azure OpenAI 路由）

· 工具调用：可挂企业系统动作

· 上下文：Enterprise Graph（自动构建）

· 安全：基于源系统的 ACL（绝不允许越权）

Glean Agents

· 可编排的 agent（研究 / 客户支持 / 销售准备）

· 工具：可调用 Glean Actions + 第三方 API

· 触发：手动 + 定时 + 事件

· 与 Assistant 集成：在 Assistant 中挂载 agent

Glean Studio / MCP / SDK

· Studio：可视化 agent builder

· MCP server：Glean 自有 MCP server

· SDK：Python / JS SDK

· API：REST API for embedding

与 WeKnora 对照：Glean 跟 Rovo 很像：都靠「Enterprise Graph + Agent 编排 + MCP」模式。WeKnora 的 ACL 路径做得比 Glean 还硬（ACL snapshot hash），差异化在「自托管 + 国产化」路径。

七、Microsoft 365 Copilot / Copilot Agents / Copilot Studio

基于 learn.microsoft.com/copilot, 2025-2026 资料。

Copilot 基础

· Copilot Chat：通用 LLM 入口

· Copilot in Word/Excel/PowerPoint/Outlook/Teams/Loop

· 数据通道：SharePoint / OneDrive / Exchange / Microsoft Graph

· 模型：OpenAI GPT-4o + 自研 Prometheus

Copilot Agents

· SharePoint Agents：站点内置 AI agent

· Copilot Studio Agents：可视化构建

· 触发：自动（基于站点事件）+ 手动

· 工具：可挂 Power Automate + 第三方 connector

· 安全：基于 M365 权限 + 治理边界

Copilot Studio / SDK / MCP

· Studio：低代码 agent + 工作流 builder

· SDK：开发者构建深度集成

· MCP：M365 Copilot 支持 MCP（2026 公告）

· Marketplace：第三方 agent 在 Teams App Store

与 WeKnora 对照：Copilot 的差异化在「跨 M365 应用」+ 「企业治理」。WeKnora 自托管路径无法直接复用 M365 数据通道，但可以借鉴「SharePoint Agents = 站点内置 agent」的概念做「KB 内置 Agent」。

九、对 WeKnora 的启示

9.1 短期（v0.7.17-v0.7.19）

· Custom Agents 抽象（v0.7.19）：instructions + 工具集 + 工作区共享，对标 Custom Agents / 妙搭

· 事件驱动触发（v0.7.19）：WebHook + Schedule，把 skills/ 接入 agent 调度

· MCP 强化（v0.7.17）：让 WeKnora 可被 Claude Desktop / 其他 MCP 客户端调用

· AI credits 配额（v0.7.19）：把 v0.7.1 模型库 + 计费集成

9.2 中期（v0.7.21-v0.7.23）

· WeKnora Studio（v0.7.21）：可视化 agent builder（Vue + 后端编排）

· 企业知识图谱（v0.7.22）：从 KB / Wiki / Agent / 数据源抽取实体关系

· 第三方 connector 联邦（v0.7.23）：当前 datasource 模块升级到联邦 RAG

· AI 治理 / DLP 子集（v0.7.20）：审计 + 敏感词 + 保留

9.3 WeKnora 差异化机会

· 自托管 + 国产化：信创栈 + 数据驻留，比 Notion / Glean 强

· doc+KB 融合的 RAG：v0.7.12-15 已经做到，是飞书级但开源可控

· ACL snapshot hash：v0.7.4-8 的 ACL 不可绕过，比 Glean 的 ACL 路径更硬

· Conditional Access + GeoIP：v0.7.14 + v0.7.16 = 自托管里第一个真正可达 IP 维度的 CA

9.4 风险与不做清单

· 不做「通用 LLM Chat」：被 ChatGPT / Claude Desktop 占位，无差异化

· 不做「跨应用 Copilot」：依赖 M365 / WPS 生态，自托管无意义

· 暂缓「Workers / 沙箱运行时」：v0.7.23+ 看市场反应再启动

· 不复制 Notion Credits：自托管场景计费模型跟 SaaS 不同
