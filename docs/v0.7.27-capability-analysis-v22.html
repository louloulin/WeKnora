六、深度差距分析

6.1 Notion 2026-03-11 API 对标

Notion 在 2025-09-03 / 2026-03-11 两个 API 版本中引入了多项关键变化，需要重点跟进：

6.1.1 data_sources 多数据源

Notion 把"Database"从单体升级为"Database parent → 多 Data Source"的层级模型。每个 Database 可挂多个独立 schema 的 Data Source，所有 Page 仍然挂在 Database 下。这是 多视图数据库 的进一步演进：一个 Database 对应"产品"概念，Data Source 对应"产品/客户/订单"等不同 schema。

WeKnora 对应方案：Build #26 已实现多视图，但 schema 仍挂在 Database 级别。v0.7.31 (#37) 将引入 Database → DataSource 二级模型，复用 Build #26 的视图层。

6.1.2 Webhooks 实时事件

Notion 在 2025-09-03 引入官方 Webhooks，事件类型覆盖 page.created / page.updated / database.updated 等，签名用 HMAC-SHA256。SDK v5 默认支持 notionVersion: "2026-03-11"。

WeKnora 对应方案：Build #33 自动化触发器中 row-changed 是内部事件（基于 service bus）。下一步把 Webhook 出站能力补齐（v0.7.31 #37），并允许外部 Webhook 推入触发 Automation（已完成 /webhooks/automations/:id）。

6.1.3 Notion Buttons 2.0

Notion Buttons 在 2026 H1 引入：

  • 按钮可以触发 Database Automation / Page Action / 发送 Slack 消息等
  • 支持 inline button（在页面内任意位置嵌入）+ block button
  • 权限粒度：按钮可调用者限定为编辑者

WeKnora 对应方案：Build #33 自动化引擎已支持 5 种 action。下一步 (v0.7.31 #37) 增加 inline button block（TipTap node + Pro 视图）+ block button + 权限绑定。

6.1.4 Notion Sites / Mail / Calendar

Notion 2026 把产品矩阵扩展到 Sites（公开页面）/ Mail（收件箱）/ Forms（表单）/ Calendar。WeKnora 目前聚焦 KB + Docs 闭环，暂不做 Sites / Mail / Calendar / Forms（避免分散）。结论：v0.7.34 之前不进入 Sites / Mail / Calendar 赛道；如企业客户需求强烈，作为 P3 评估。

6.2.1 飞书多维表格 2.0 核心新特性

  • 工作流引擎（IFTTT 2.0）：可视化 DAG 配置触发器 + 节点 + 分支。

6.3 Tana Supertags · AI Autofill · Live Transcribe 对标

6.3.1 Supertags 核心模型

Tana Supertag 是一种"带 schema 的标签"。例如 #person supertag 定义 schema：

name        : text      (required)
email       : text
birthday    : date
company     : link → #company
projects    : multi-link → #project

任何节点被赋予 #person 后，自动继承上述字段 + 类型校验 + 反向引用。Tana 2026 进一步支持：

  • Child Supertag：父节点的子节点自动继承 supertag（如 Library 下的所有节点自动是 #article）
  • AI Autofill：节点添加 supertag 后，AI 自动从内容抽取字段值填入
  • AI Autotag：批量节点自动建议 supertag
  • Commands on add：节点被赋予 supertag 时自动触发命令（如自动移到 Library / 自动加引用）

6.3.2 WeKnora v0.7.29 计划

Build #35 将引入 supertags / entities / entity_relations 三表 + 抽取管道，对标 Tana：

  • Supertag 模型：JSONB schema + 字段类型 + 必填校验
  • 自动抽取：LLM NER + 关系抽取 + 实体合并（向量相似度 ≥ 0.92）
  • Child Supertag：树形结构继承
  • AI Autofill：节点附加 supertag 后异步抽取字段
  • Commands on add：复用 Build #33 Automation 引擎作为命令执行器

关键差异化：WeKnora 把 Supertag 嫁接到 知识库语义（跨 KB 文档 + 多维表行），而 Tana 只在单一 outliner 内。意味着 WeKnora 知识图谱可跨文档 / 跨表 / 跨 KB 自动关联。

6.4 Coda Packs SDK 2.0 · Sync Tables · Agents 对标

6.4.1 Packs SDK 2.0 核心抽象

Coda Packs 是开发者构建"自定义 building block"的 SDK。2.0 引入：

  • Sync Table：声明 schema + fetcher，Coda 自动调度 + 增量同步 + 列自适应
  • Dynamic Sync Table：用户在 Coda UI 里选择 URL，Pack 返回该 URL 的 schema（典型用例：Notion database → Coda table）
  • Formula：声明参数 + 返回值，Coda 包装成可在 doc 内调用的函数
  • Sync Execution Context：continuation.pageToken 实现分页 / temporaryBlobStorage 实现大文件缓存
  • Per-user OAuth2：每个 Coda user 独立 token，Pack 用用户身份调用第三方 API
  • Network Domain Whitelist：必须声明访问的域名，Coda 沙箱化执行

十一、v0.7.29 详细设计：知识图谱 · Supertags · 自动关系抽取（Build #35）

11.1 目标

  • 从 KB 文档 / 多维表行 / 协作文档 自动抽取实体（人物 / 组织 / 项目 / 概念 / 时间）+ 关系（雇佣 / 属于 / 参与 / 相关于）→ 知识图谱
  • 引入 Supertags：带 schema 的标签，可绑定字段类型与必填项
  • 为 v0.7.29.5 AI Verification 提供"实体级信任分"

11.2 数据模型

CREATE TABLE supertags (
    id              BIGSERIAL PRIMARY KEY,
    tenant_id       TEXT NOT NULL,
    kb_id           TEXT NOT NULL,
    name            TEXT NOT NULL,
    color           TEXT,
    schema          JSONB NOT NULL,           -- [{name, type, required}]
    icon            TEXT,
    child_supertag  BOOLEAN NOT NULL DEFAULT false,
    autofill_model  TEXT,                     -- gpt-4o / deepseek / doubao
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE entities (
    id              BIGSERIAL PRIMARY KEY,
    tenant_id       TEXT NOT NULL,
    kb_id           TEXT NOT NULL,
    supertag_id     BIGINT REFERENCES supertags(id),
    name            TEXT NOT NULL,
    properties      JSONB NOT NULL DEFAULT '{}',
    embeddings      BYTEA,
    first_seen_doc  BIGINT,
    last_seen_doc   BIGINT,
    occurrence      INT NOT NULL DEFAULT 1,
    trust_score     REAL NOT NULL DEFAULT 1.0,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE entity_relations (
    id              BIGSERIAL PRIMARY KEY,
    src_entity_id   BIGINT NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
    dst_entity_id   BIGINT NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
    relation        TEXT NOT NULL,
    weight          REAL NOT NULL DEFAULT 1.0,
    evidence_docs   JSONB NOT NULL DEFAULT '[]',
    confidence      REAL NOT NULL DEFAULT 1.0,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (src_entity_id, dst_entity_id, relation)
);

CREATE TABLE supertag_commands (
    id              BIGSERIAL PRIMARY KEY,
    supertag_id     BIGINT NOT NULL REFERENCES supertags(id) ON DELETE CASCADE,
    event           TEXT NOT NULL,            -- on_add / on_remove / on_update
    automation_id   BIGINT NOT NULL,          -- -> Build #33 automation
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_entities_tenant_kb ON entities(tenant_id, kb_id);
CREATE INDEX idx_entities_supertag ON entities(supertag_id);
CREATE INDEX idx_relations_src ON entity_relations(src_entity_id);
CREATE INDEX idx_relations_dst ON entity_relations(dst_entity_id);
CREATE INDEX idx_supertags_tenant ON supertags(tenant_id);
CREATE INDEX idx_supertag_commands ON supertag_commands(supertag_id, event);

11.3 抽取管道

  1. 实体识别（NER）：LLM zero-shot，输入文档段落，输出实体列表 {name, type, evidence_span}
  2. 关系抽取（RE）：对每对共现实体，LLM 判断关系类型 + 置信度
  3. 实体合并：向量相似度 ≥ 0.92 触发合并（保留 trust_score 较高）
  4. Supertag 绑定：根据实体类型自动建议 supertag，管理员确认后绑定
  5. AI Autofill：节点添加 supertag 后异步抽取字段（基于上下文）
