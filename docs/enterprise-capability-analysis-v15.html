3.2 REST 端点（3 条）

· POST /api/v1/assistant/ask 提交问题，返回结构化响应

· GET /api/v1/assistant/conversations?limit&offset 列出该租户的近期问答

· GET /api/v1/assistant/conversations/:id 拉取一个会话的所有轮次

3.3 wire 形状

AssistantAskRequest：{query, source_kb_ids[], include_wiki, max_results_per_source, conversation_id}

AssistantAskResponse：{answer_id, conversation_id, answer_text, kb_citations[], wiki_citations[], model_name, latency_ms, result_count, created_at}

AssistantCitation：{type, id, title, slug, kb_id, snippet, score}

3.4 服务层核心逻辑

Ask 热路径：校验 query 非空、tenant_id > 0 → 默认 MaxResultsPerSource=5、clamp [1,20] → ConversationID 自动 UUID → 并行 KB 检索（SearchKnowledgeForScopes）和 Wiki 检索（WikiSearchV2Service.Search，按需开关）→ 剥离 Wiki <mark> 标签 → 合成占位 answer_text（保留 KB/Wiki 计数 + 顶部 snippet）→ 持久化一行（KB/Wiki citations + 源 KBIDs + 延迟）→ 返回响应。失败时不撤销响应；持久化失败仅记日志。
范围澄清：v0.7.15 后端只解决 §3.3 描述的检索 / 审计层。LLM 真实调用、对话管理 UI、流式输出、反馈循环放在 v0.7.17。前端面板通过同一组端点对接，后端契约稳定即可平滑升级。

四、对标飞书（Feishu / Lark）— 重点：文档 + 同步块 + 知识问答

飞书是国内 doc+KB 一体化最完整的产品。本节聚焦飞书公开资料（feishu.cn/product/docs, wiki, feishuai, security, pricing，2026 年 8 月访问）。

飞书同步块（同步块 / Sync Blocks）

用户对一个文档块（block）选择"同步"，可嵌入到任意其他文档；源块更新 → 全部嵌入实例同步刷新。这是飞书跨文档知识复用的核心原语，WeKnora Wiki 目前缺少这一原语。

P1 大差距

对标对象：Notion Synced Blocks / Microsoft Loop components。

飞书知识问答（AI RAG Q&A）

飞书 AI 旗舰版含知识问答模块：对企业知识库做 RAG 检索 + LLM 生成；按 AI credits 计费（旗舰版 20M credits/yr）。WeKnora v0.7.15 后端是这个能力的检索底层，前端 + LLM 接入是 v0.7.17。

检索层已就位 前端 / LLM 待补

飞书企业级 IAM

SAML/OIDC SSO 至企业 IdP、2 步验证、域管理、终端管控、按应用 + 按文档权限、专属安全密钥（CN 数据中心）；高级账号安全在商业旗舰版及以上。WeKnora v0.7.6-14 已闭环等同能力。

对标持平

飞书多维表格（Bitable）

类 Airtable / Notion Database + 强 AI 字段（AI 字段、侧栏、仪表盘）+ 行级权限。是飞书相对通用 Wiki 的最大差异化。WeKnora 当前 0% — 这是个独立模块工程量。

P2 大差距

飞书应用 + aPaaS / 飞书妙搭

低代码搭建 AI 应用（妙搭）、豆包工作伙伴、aily desktop、Miaojì 会议纪要、项目 AI、Agent 编排。是飞书相对 Notion / Confluence 的 AI 深度差异化。

P2 差距

飞书 AI 定价

基础版 ¥9,900/yr（180k credits）/ 企业版 ¥99,000/yr（2M）/ 企业 Plus ¥~（6M）/ 旗舰版 ¥~（20M）。WeKnora 自托管开源路径无 SaaS 计费，但缺少 credits 模型与 AI 资源配额控制。

计费 / 配额 待补

飞书差距综合：① 同步块（实时协作）= WeKnora 0%；② 多维表 = 0%；③ AI 应用生态 / 妙搭 = 0%；④ AI credits 配额 = 0%。这四项是把 WeKnora 拉到飞书级别的硬骨头。
持平 / 超越：IAM 控制平面、知识问答检索层（v0.7.15 后端）、文档 / Wiki CRUD、引用 / 回链。

五、对标 Notion — 重点：Synced Blocks / Custom Agents / Enterprise Search

Notion 是 doc+KB 全球对标最直接的产品。本节聚焦 notion.com/product/ai, security, pricing, help/data-residency。

Notion Synced Blocks

与飞书同步块同构：跨页面同步的块，原块改 → 嵌入实例同步。Notion Plus 起无限。可组合、可嵌套、跨工作区引用。

数据库之间可建双向关联字段 + rollup。WeKnora 当前 KB ↔ Wiki 是单向引用关系（v0.7.12-13），但缺数据库抽象。

P2

Notion Agent = chat/generate/autofill/translate；Custom Agents 可构建一次后工作区共享，按 Notion credits 计费（$10/1k credits）。WeKnora 未来需要类似 Agent 框架 + 计费模型。

P1

Notion Enterprise Search（联邦检索）

跨 Slack / GDrive / GitHub / Jira 等做 RAG 联合检索（Beta）。WeKnora 当前是单租户内部检索，缺联邦。

P2

Notion 实时协作 / multiplayer blocks

块级多人协作 + live cursors + presence + offline sync + per-block comments + @mentions。WeKnora 当前无 Yjs 实时协作。

P1 大差距

SAML SSO（Business+）、SCIM（Enterprise）、2 步验证、admin roles、per-database permission、permission groups、private teamspaces。Conditional access 委托给 SSO IdP（不原生地做）。

七、对标 Glean — 重点：Enterprise Graph + Assistant + Agents

Glean 是 2024-2026 增长最快的 enterprise AI 搜索 / 助理。本节聚焦 glean.com, docs.glean.com。

Glean Assistant（Glean Chat）

基于企业内容 + 模型无关（Anthropic / OpenAI / Azure OpenAI 路由）+ 工具调用 + 工作流编排。WeKnora v0.7.15 后端的 KB+Wiki 融合是 Glean Assistant 的最简内部版本。

v0.7.15 后端 = 检索层 LLM / 工具调用 待补

Glean Enterprise Graph

自动发现 + 维护企业内容实体的关系图（人 / 文档 / 项目 / 主题），是 Glean 上下文感知的核心。WeKnora 当前 AuthZ 元组可作为最简图存，但缺自动发现 / 主题聚合层。

P2

Glean Agents

可编排的 agent（研究 / 客户支持 / 销售准备），挂到 Assistant 工作流中。WeKnora 当前 internal/application/service/agent_service.go 已有基础 Agent，但缺像 Glean Agents 这种「研究类长任务」抽象。

P2

Glean Connectors（联邦检索）

100+ 联邦连接器（Slack / SharePoint / GitHub / Salesforce / Jira ...），统一进 Enterprise Graph。WeKnora 已有 datasource 模块和若干内置连接器，但缺「联邦 RAG」抽象。

P2

Glean Permissions（基于源系统的 ACL）

关键设计：每个 connector 走源系统的 ACL，绝不绕过访问控制。WeKnora AuthZ 已经做到这一点（v0.7.4-8），KBAccessRead/Write ACL 中间件严格基于 ACL snapshot hash。

持平

Glean ISO 42001（AI 治理）

2025 年首批拿到 ISO/IEC 42001:2023 AI 管理系统认证的产品之一。WeKnora 暂无 AI 治理证书。

P3

Glean 差距综合：① Enterprise Graph 自动建图 = 0%；② Connectors 联邦 RAG = 0%；③ Agents 编排 = 0%；④ AI 治理（ISO 42001）= 0%。

八、对标 Microsoft Loop / Microsoft 365 Copilot

Loop 是 M365 阵营的 doc+KB 模块。本节聚焦 learn.microsoft.com/loop。

Loop components（Fluid Framework）

Loop 的核心原语：跨 Word / Excel / PowerPoint / Outlook / Teams 同步的块，本质就是微软版「同步块」。WeKnora 0%。

P1 大差距

Microsoft 365 Copilot in Loop

Copilot 通用 LLM + 表格洞察 + 内容生成。Copilot 数据通道走 SharePoint / OneDrive / Exchange，依赖 M365 已有索引。WeKnora 自托管路径不依赖 M365 数据通道。

P2

Entra ID + Microsoft Purview

Loop 依赖 Entra ID 做 SSO/Conditional Access/MFA/SCIM/PIM/Identity Governance；Purview 提供审计 / eDiscovery / 保留 / DLP / 客户密钥。WeKnora v0.7.6-14 IAM 控制平面 = Entra ID 子集，Purview = 0%。

IAM 持平 Purview 0%

Microsoft 365 多地理（Multi-Geo）

按用户 / 工作区首选数据位置。WeKnora 自托管可让用户部署到任意区域，但缺产品化的「多区域一键切换」抽象。

P3

Loop 当前状态

Microsoft 365 的 Loop app 仍是 public preview；外部分享当前不支持（"Loop currently doesn't support external sharing for guests"）。这是 Loop 的弱点；WeKnora 自托管不受此限。

WeKnora 优势

Loop 定价

Loop app 随 M365 商业订阅免费；Copilot 加购 $30/user/月。WeKnora 自托管开源路径无此计费。

自托管开源

Loop 差距综合：① Loop components / Fluid Framework = 0%（与飞书同步块、Notion Synced Blocks 同档）；② Purview 套件（DLP / eDiscovery / Customer Key / 保留）= 0%；③ M365 Copilot 路径 / M365 数据通道集成 = 0%。
持平 / 超越：IAM 控制平面（v0.7.6-14）、外部分享（自托管不受 Loop 限制）。
