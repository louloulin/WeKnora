四、Provider 接口设计

核心契约

type Provider interface {
    Complete(ctx context.Context, req Request) (Response, error)
    Stream(ctx context.Context, req Request, sink EventSink) error
    Name() string
}

type Request struct {
    Query          string
    ConversationID string
    KBCitations    []types.AssistantCitation
    WikiCitations  []types.AssistantCitation
    ModelName      string
    MaxTokens      int
    Temperature    float64
    SystemPrompt   string
}

type Event struct {
    Type  EventType  // token | citation | done | error
    Data  any
    Error error
}

var ErrProviderUnavailable = errors.New("llmstream: provider unavailable")
var ErrProviderTimeout    = errors.New("llmstream: provider timeout")
func IsTransient(err error) bool { ... }

关键设计决策

· Provider 必填：构造器不为 nil 时默认 NoopProvider，让 DI 误配在启动时爆炸

· Citation 作为 Request 字段：让 provider 自己决定 prompt 编排，不在 transport 里塞 RAG 逻辑

· Provider 自报 ModelName：避免 assistant service 维护一张模型 → provider 的映射表

· Event 用 any Data：避免 5 种 Event 都开 struct 接口，平衡类型安全与扩展性

· ErrProviderUnavailable / Timeout + IsTransient：让 handler 自动把 5xx 分类

· FuncSink 适配器：让测试用 5 行代码就能驱动整个 Stream 路径

NoopProvider 设计

· 与 v0.7.15 composeAnswerPlaceholder 输出字节级一致，所以现有前端不需要改

· Complete 返回 Response，Stream 走 1 个 token + 1 个 done

· ModelName = "noop"（让审计日志能区分真 LLM 与 placeholder）

· 让 dev 环境 / 单元测试在没有真 LLM key 时也能跑完整链路

添加 OpenAI Provider 的步骤

  1. 新建 internal/llmstream/openai.go：实现 Provider 接口
  2. 选 SSE 客户端（推荐 github.com/sashabaranov/go-openai 或自写 sse reader）
  3. 把 Request.KBCitations + WikiCitations 拼成 RAG prompt
  4. 把 stream 事件映射到 EventToken（OpenAI 流式 delta）
  5. 错误码映射：429 / 5xx → ErrProviderUnavailable，timeout → ErrProviderTimeout
  6. container.go: 把 func() llmstream.Provider { return llmstream.NoopProvider{} } 改成 func() llmstream.Provider { return llmstream.NewOpenAIProvider(os.Getenv("OPENAI_API_KEY"), "gpt-4o-mini") }

八、前端面板对接（消费 SSE）

v0.7.17 mockup docs/ai-assistant-panel-mockup-v0.7.17.html 已展示面板 UI，本节说明 Vue 组件怎么消费 SSE 端点。

8.1 推荐实现：fetch + ReadableStream

// frontend/src/api/assistant.ts
export async function askStream(
  req: AssistantAskRequest,
  onCitation: (c: AssistantCitation) => void,
  onToken: (text: string) => void,
  onDone: (info: DoneEventData) => void,
  onError: (err: string) => void,
  signal?: AbortSignal,
): Promise<void> {
  const resp = await fetch("/api/v1/assistant/ask?stream=1", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(req),
    signal,
  });
  const reader = resp.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = "";
  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    // 按 \n\n 分帧，逐帧 parse
    let idx;
    while ((idx = buffer.indexOf("\n\n")) !== -1) {
      const frame = buffer.slice(0, idx);
      buffer = buffer.slice(idx + 2);
      const { event, data } = parseSSEFrame(frame);
      switch (event) {
        case "metadata":  /* save conversation_id */ break;
        case "citation":  onCitation(JSON.parse(data).citation); break;
        case "token":     onToken(JSON.parse(data).text); break;
        case "done":      onDone(JSON.parse(data)); break;
        case "error":     onError(JSON.parse(data).error); break;
      }
    }
  }
}
为什么不直接用 EventSource：浏览器 EventSource 不支持 POST body + 自定义 header（Authorization），所以走 fetch + ReadableStream 手动解 SSE frame。AbortSignal 让用户在流式生成时点"停止"按钮生效。
