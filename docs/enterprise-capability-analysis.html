一、执行摘要

当前分支已经不是“单纯 RAG Demo”：它具备完整的知识库、Wiki 页面、中文/模糊搜索、智能体、共享空间、RBAC、审计、缓存、批处理和评测基础。要达到企业级产品，重点不是继续堆功能，而是把已有能力升级为可治理、可隔离、可恢复、可计量、可审计的产品平台。

强项 当前已具备

知识理解、Wiki 内容治理、RAG/Agent、空间协作、页面 ACL、中文搜索与评测闭环。

P0 必须补齐

统一身份与权限策略、控制面/数据面分离、备份恢复与灾备、可观测性 SLO、租户配额与成本治理。

12 个月 建议节奏

先完成安全和可靠性底座，再做规模化数据平面、企业集成与 AI 质量运营。

一句话判断：WeKnora 在“知识工作台”和“Wiki-RAG 体验”上有差异化；与顶级项目的主要差距位于企业控制平面，而不是检索算法数量。

以下结论来自当前分支的路由、服务、迁移、前端视图、测试与已有 Comet 规格，不把规划文档误当成已实现功能。

检索与智能体

已实现ReAct Agent、工具调用、Reflection、多轮上下文、Tool Cache、Citation Evidence、MCP、网络搜索和沙箱能力。

五、目标企业级架构

核心原则：控制平面统一治理，数据平面可水平扩展；同步请求只做编排，所有长任务事件化；策略、审计、成本和 trace 贯穿每个租户边界。

关键架构改造

1. 统一请求上下文

建立 TenantContext、Principal、PolicyDecision、TraceContext、CostContext 五元上下文；禁止 repository 在缺失租户上下文时执行跨租户查询。

2. 事件化数据平面

上传、解析、切分、向量化、索引、回链、评测统一使用 outbox + worker + DLQ；任务状态可查询、重试、取消、补偿和重放。

3. 策略中心

路由只做粗粒度 API capability，资源访问统一调用 AuthZ；策略支持版本化、模拟、解释、审批和缓存失效。

4. AI 控制平面

模型、Prompt、工具、索引和评测都带版本；支持灰度、回滚、质量门禁、成本预算和线上反馈回流。

六、OpenBuddy × Casdoor × WeKnora 一体化

用户所称的“cardoor”按 OpenBuddy worktree 中实际存在的 Casdoor 分支分析：codex/casdoor 与 comet/casdoor-enterprise-identity。它们已经形成企业身份、租户 principal、会话绑定和本地资源门禁的实现基础，但尚未自动等价于 WeKnora 的服务端权限；一体化必须把身份事实、策略决策、资源执行和 Agent 副作用审批分层。

分支事实：codex/casdoor 当前包含商业治理、钱包/配额、成本归因、审计与 Casdoor 管理面；comet/casdoor-enterprise-identity 已完成 Casdoor OIDC/PKCE、组织租户、角色/权限、会话 tenant+subject 绑定、资源授权、账户安全、规则模拟与 Webhook 订阅。其正式文档仍明确列出服务端共享资源模型、后端/网关重复校验、租户生命周期和集中式审计为后续工作，不能把本地 Electron 门禁当作云端安全边界。

必须补齐的跨产品协议

Token Exchange

OpenBuddy 不把 Casdoor refresh token 传给 WeKnora；由 Gateway 或 WeKnora Auth Broker 将已验证 Casdoor principal 换成短期、audience 固定、tenant 固定的 WeKnora access token。token 至少包含 iss/sub/aud/exp/jti/tenant_id/session_id/membership_version，并支持 revoke 快速失效。

Policy Decision

统一接口：authorize(subject, tenant, resource, resourceId, action, context) 返回 allow/deny/reason/decision_id/policy_version/expires_at。WeKnora 的资源 ACL 是第二层约束，不能被 Casdoor 的粗粒度 capability 覆盖。

Revocation

Casdoor webhook / introspection 触发 Gateway、OpenBuddy 和 WeKnora 的 tenant membership cache、session index、authorization cache 失效；撤销必须按 subject、tenant、session、token jti 传播并可重放。

Audit & Evidence

同一 correlation_id 串联登录、租户切换、策略决策、WeKnora 资源访问、Agent tool call、审批、模型消耗和最终结果；token、密码、PII 原文和 Prompt secret 不写审计。

主要攻击面与防线

Tenant Confusion

签名 token 的 tenant 与路径/请求体不一致时拒绝；repository 和 SQL 仍必须带 tenant 条件；共享资源用显式 grant。

Stale Membership

membership_version、短期 token、webhook 失效和 introspection 兜底；租户暂停立即阻断新请求。

Confused Deputy

OpenBuddy 的 Agent 不能凭用户登录态代表用户执行任意 WeKnora 写操作；每个工具声明 data scope、allowed action、approval 和 expiry。

Token Leakage

token 只在 Main/Gateway；前端只拿脱敏 session；日志和诊断包做字段级 redaction；桌面存储使用系统安全存储。

Replay / Duplicate

请求携带 jti、nonce、expiry、idempotency key；任务、Webhook、账单结算和批处理必须幂等。

Cache Leakage

所有授权缓存 key 必须含 issuer、subject、tenant、resource、policy_version；ACL 和 membership 变更主动失效。

八、企业级验收指标

安全

  • 跨租户读写负向测试覆盖所有资源类型。
  • 高风险操作 100% 有 actor、reason、trace、before/after 审计。
  • 密钥不落日志；轮换后旧 token 按策略失效。
  • 插件和 Webhook 具备签名、权限声明和重放保护。
  • Casdoor→Gateway→WeKnora 三层拒绝结果一致。

可靠性

  • 核心 API、异步任务、模型调用都有 trace/span。
  • 关键 SLO 有告警、值班路由和演练记录。
  • 任务重试幂等；DLQ 可检索、重放和审计。
  • 备份恢复按季度演练并保留证据。

AI 质量

  • 回答关联模型、Prompt、工具、索引和知识版本。
  • 引用正确率、召回率、延迟、成本可按租户/应用查询。
  • 模型或 Prompt 发布必须通过离线评测门禁。
  • 线上用户反馈可自动进入 Badcase 数据集。

性能

  • 明确 P50/P95/P99：登录、检索、首 token、完整回答、批任务。
  • 百万文档、十万页面、并发租户和大文件有压测报告。
  • 限流、配额和 noisy-neighbor 防护可观测。
  • 索引蓝绿切换不阻断读流量。

运维

  • 新环境配置预检能在启动前报告缺失依赖。
  • 升级自动备份、迁移预检和失败回滚。
  • 诊断包不泄露 PII/密钥，可复现关键问题。
  • Lite、单机 Compose、Kubernetes 支持矩阵明确。

产品

  • 管理员可见用户、空间、资源、成本、质量和审计全景。
  • API、SDK、Webhook、插件都有版本兼容策略。
  • 文档、教程、示例和错误信息可完成自助排障。
  • 企业功能均有开关、授权、审计和降级策略。
